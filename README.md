# NearView · 近屏

NearView 是一个面向可信局域网的点对点屏幕共享桌面应用。它不要求注册账号，也不需要部署公网服务器：一台设备创建房间后，其他设备可自动发现，或通过 `IP:端口` 手动加入。

项目目前是可运行的 **0.1 MVP**，优先支持 Windows。网络层、媒体层和捕获层没有绑定 Radmin VPN 的私有协议，因此可以运行在普通局域网、Radmin VPN、ZeroTier、Tailscale、WireGuard 等虚拟网卡之上。

## 已实现

- UDP 组播自动发现房间，并显示房主、IP、人数和是否加密。
- 手动输入 `IP:端口` 加入，解决部分网络禁用组播的问题。
- 可选多网卡绑定，界面会标注 VPN/虚拟网卡。
- 房主内置 WebSocket 信令服务，无需额外部署。
- 最多 8 人规模的 WebRTC P2P Mesh 屏幕流，支持多人同时共享。
- 整屏或单窗口捕获，可选系统声音。
- 多人宫格、单人聚焦、原生画中画与全屏查看。
- 三档画质：文字优先 1080p、均衡 1600×900、流畅 720p/60fps。
- 带观看者昵称的点击光圈和拖拽箭头，标注自动消失。
- 房间聊天、剪贴板文本一键投递、单条消息复制。
- 隐私暂停：停止发送实时帧，改为发送冻结画面。
- 房主密码使用盐化 `scrypt` 摘要校验；媒体由 WebRTC DTLS-SRTP 加密。

## 快速开始

要求 Node.js 22+ 与 pnpm 10+。

```bash
pnpm install
pnpm dev
```

生产构建：

```bash
pnpm build
pnpm package
```

构建产物位于 `out/`，安装包位于 `release/`。

Windows 首次运行会请求“专用网络”防火墙权限。至少允许房主接收 TCP 连接；局域网自动发现还依赖 UDP `42399` 组播。

## 使用方式

1. 两台设备接入同一个局域网或同一个 Radmin VPN 网络。
2. 首页选择实际承载双方通信的网卡。Radmin VPN 用户应选择名称中含 `Radmin` 的虚拟网卡。
3. 一台设备点击“创建房间”，另一台设备从“可加入的房间”进入。
4. 如果组播不可用，房主点击房间右上角的链接按钮复制 `IP:端口`，好友通过“地址加入”输入该地址。
5. 点击“共享我的屏幕”选择整个屏幕或应用窗口。

## 架构

```text
              UDP multicast :42399
        ┌─────────────────────────────┐
        │  房间公告 / 自动发现 / 心跳  │
        └──────────────┬──────────────┘
                       │
访客 A ── WebSocket ───┤
                       ├── 房主内置信令服务（随机端口）
访客 B ── WebSocket ───┘
        │
        ├──────── WebRTC 加密媒体（P2P Mesh）──────── 房主屏幕
        ├──────── WebRTC 加密媒体（P2P Mesh）──────── 访客 A 屏幕
        └──────── WebRTC 加密媒体（P2P Mesh）──────── 访客 B 屏幕
```

房主只转发 SDP、ICE 和房间级消息，不转发屏幕画面。屏幕流直接走 WebRTC host candidate，因此不依赖 STUN/TURN，也适合没有互联网出口的隔离网络。

当前 Mesh 上限按 8 人设计。每个共享者会向每位观看者单独编码、上传，人数继续增长时应升级为 SFU 拓扑。

## 安全边界

- WebRTC 媒体使用标准 DTLS-SRTP 加密。
- 房间密码在房主进程中以盐化摘要形式保存，单次连接后不会回传。
- 信令 WebSocket 默认是明文 `ws://`，房间密码会发送给房主。NearView 面向你信任的局域网和虚拟专用网络，不应直接暴露在公共 Wi-Fi 或公网端口上。
- 自动发现公告是未认证的局域网广播。恶意节点可能伪造房间信息。
- 当前版本没有指纹校验和 TURN 中继，无法抵御局域网内的主动中间人攻击；对高敏感内容请先建立可信的 VPN/局域网。

更完整的威胁模型见 [SECURITY.md](SECURITY.md)。

## 已知限制与路线图

- 当前实现以 Windows 为主；Electron 与 WebRTC 跨平台基础已具备，但 macOS 屏幕录制授权和 Linux 桌面捕获仍需实测。
- 系统声音回环主要依赖 Windows Chromium 实现；其他平台可能需要额外驱动。
- 当前通过编码约束与码率上限调节画质，尚未完成真正的 Simulcast 三层码流选择。
- 没有账号、云端目录、远程控制或公网穿透；这些都是明确的产品边界。
- 后续优先级：真实 Simulcast、焦点按需订阅、8 人以上 SFU、连接质量统计、房间二维码、应用签名与自动更新。
